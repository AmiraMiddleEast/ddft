# Plan 07-04 — Admin: Behörden, CoGS chambers, settings

<objective>
Translate the admin surface — authority maintenance, document types, CoGS chambers,
and the API-key/model settings screen.
</objective>

<constraints>
Same as 07-01. This plan carries the highest risk of translating DATA instead of
UI, so be strict:
- Authority `name`, `address`, `phone`, `email`, `website`, `officeHours`, `notes`,
  `specialRules` are DB VALUES rendered into forms and tables. Translate the FIELD
  LABELS only; never the values or the placeholder examples that mirror real data.
- Document-type display names are proper nouns AND resolver inputs
  (`lib/behoerden/match-doc-type.ts`). Never translate them, and never change the
  `id` slugs.
- CoGS chamber names (Ärztekammer/Zahnärztekammer …) are proper nouns.
- `lib/settings/store.ts` — translate only user-facing message strings. Do NOT
  change setting KEYS (e.g. the anthropic key/model setting names) or the default
  model id `claude-sonnet-4-6`.
</constraints>

<must_haves>
- Admin overview, authority list + filters, create/edit authority forms read in English
- Document types screen reads in English while listing German type names verbatim
- CoGS list and edit form read in English
- Settings screen (API key + model) reads in English
- No document-type slug or display name changed; resolver behaviour identical
- `npx tsc --noEmit` passes; `npx vitest run lib/behoerden` still 34 passing
</must_haves>
